# Built-in recovery control — 2026-10-12

Requested comparison against the largely built-in 4.19 configuration. The native 5.15 diagnostic already builds USB glue/PHY support into the Image, but still has 149 native loadable modules. This separate control selects the 148 formerly modular native configuration symbols as built-in and disables CONFIG_MODULES, while keeping VA39, EFI disabled, no LTO and no pre-MMU marker writes. The full Image built after fixing two pre-existing CONFIG_MODULES=n compile errors: Qualcomm minidump module dump helpers and Android debug-kinfo module layout offsets. Both fixes are published on the experimental kernel branch at 5870a360d2c9. The packaged embedded configuration matches the object configuration, and the ramdisk omits /lib/modules entirely. No recovery boot is claimed.

The private recovery ramdisk starts ADB before recovery UI, requests root ADB and is globally permissive. Root ADB was verified on 4.19 (UID 0 and su context), allowing direct read-only collection of the actual firmware DTB and inactive boot partition backups. Private authorization material and raw device data are not published.

This is a recovery isolation experiment. External display/audio/camera/GPU/vendor modules are not converted by this native-only configuration; the production Android source profile still uses its matching 207-module bundle. Only a measured boot result can justify promoting the needed built-in dependencies.

The native DTB/DTBO built-in-only test returned to fastboot before ADB. A full working 4.19 DTB/DTBO control with the same 5.15 Image also exposed no USB; physical reset was requested. These observations weaken module loading as the sole cause, but do not establish how far the kernel executed.

Strict code-diff style checks passed for both fixes. MODULES=n full-Image compilation and MODULES=y affected-object compilation passed. W=1 object preparation failed in unchanged arm64 vDSO code on three missing prototypes, as it did before these changes; no warning suppression was introduced. A legacy checkpatch invocation that includes commit metadata rejects the modern Assisted-by tag and requires a human Signed-off-by; code-only checks exclude that metadata.

After physical reset, the matched 4.19 diagnostic recovery was restored and verified with UID 0, global permissive mode and an empty pstore. Its boot reason was a hard/cold reset, confirming why RAM retention cannot be assumed. The built-in-only uncompressed 5.15 Image then also returned to fastboot with the native DTB/DTBO.

The 5.15 mapping code explicitly retains physical sub-2MiB misalignment in x23 and adds it to both virtual mapping and relocation, so the legacy header offset alone does not establish a mapping bug. No virtual-address-layout patch was made. A private first-word-branch header experiment preserves the original branch target and every byte after the first eight; its result is pending. This intentionally modified header is separate from source-matching production images.
